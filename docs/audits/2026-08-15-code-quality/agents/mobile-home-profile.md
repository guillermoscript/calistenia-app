# Mobile: home/profile/onboarding/ui/lib

## Grade
**C+** — The `lib/` glue layer (auth, avatar, storage, style-selfcheck, day-rollover, whats-new) and the `components/ui/` primitives are genuinely well-engineered: documented, single-purpose, defensively coded against real production incidents. But the screen layer (`reminders.tsx`, `profile.tsx`, `OnboardingFlow.tsx`) re-implements — almost line-for-line — business logic that already exists (or should exist) in `packages/core`, resulting in three god-screens and real drift risk between web and mobile. One dead dependency directly contradicts the project's own documented architecture decision.

## Top 3 refactors
1. **Extract the reminders "timeline" domain logic** (day labels, meal icons, hour/minute clamping, `TimelineItem` shape, pause-window expansion, save-error mapping) out of `apps/mobile/src/app/reminders.tsx` and `apps/web/src/pages/RemindersPage.tsx` into `packages/core/lib/reminders-timeline.ts` (or a `useRemindersTimeline` hook). This alone would cut ~150 duplicated lines and remove the single biggest DRY violation in scope.
2. **Extract onboarding wizard mutations into a core hook.** `handleSaveBasics/Goals/Health/Training` + the `body_measurements` insert are duplicated verbatim between `apps/mobile/src/components/onboarding/OnboardingFlow.tsx` and `apps/web/src/components/onboarding/OnboardingFlow.tsx`. A shared `useOnboardingWizard(userId)` hook in `packages/core` would remove the duplication and the drift risk (mobile and web already read PII from `nutrition_goals` with copy-pasted comments explaining the same gotcha).
3. **Break up `profile.tsx` into a `ProfileMenuRow` component + a `useProfileBody` core hook.** Nine near-identical icon/title/desc/chevron blocks should become one reusable row component; the weight/height/age/sex/activity load+save block (lines 109–173) duplicates `apps/web/src/pages/ProfilePage.tsx:100-221` verbatim and belongs in core, not copy-pasted per platform.

## Done well
- **`lib/auth.ts`, `lib/use-auth-user.ts`, `lib/avatar.ts`, `lib/use-avatar-upload.ts`** — textbook separation of concerns: pure, testable logic (`avatar.ts` has zero RN/Expo/`pb` imports by design, documented as "the only layer of this feature the mobile tests can exercise"), with the OAuth flow's Custom-Tabs-freeze workaround and the avatar MIME/size validation both thoroughly reasoned in comments.
- **`lib/style-selfcheck.ts`, `metro.config.js`** — both are directly traceable to real production incidents (duplicate `react-native-css-interop` / duplicate React copies) and fix them at the right layer instead of papering over symptoms.
- **`components/ui/button.tsx`, `components/ui/card.tsx`** — proper CVA-driven explicit variants and genuine compound components (`Card`/`CardHeader`/`CardTitle`/`CardContent`/`CardFooter`), matching the composition-patterns guidance.
- **`components/ui/option-sheet.tsx`, `components/QuickMenu.tsx`, `components/WhatsNewModal.tsx`** — consistently use native `<Modal animationType="slide">` per the project's own documented anti-gorhom convention (making the `_layout.tsx` gorhom import in H4 a real outlier, not the norm).
- **`components/home/HomeActivity.tsx`** — good example of one-pass derivation (`flatMap`+`filter`+`map` combined per the `js-flatmap-filter` rule), hoisted regex, extracted `TabButton`/`ActivitySkeleton` subcomponents, and correctly documents the nested-Pressable-on-Android gotcha with matching accessibility labels.
- **`lib/use-day-rollover.ts`** — a small, focused hook with a ref-held callback specifically to avoid re-subscribing listeners — exactly the pattern the "unstable callbacks" guidance asks for.
