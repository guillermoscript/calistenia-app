# Mobile — Nutrition & Pantry

## Grade
**B-.** Leaf-level craftsmanship is genuinely strong: consistent `Pressable`/`expo-image` usage, deliberate `memo` discipline in several places (`NutritionDashboard`'s `MealCard`, `PantryTable`'s `Row`), well-documented platform gotchas (MIUI-safe native `Modal`, Android widget renderer constraints), and clean pure-function extraction in `lib/`. But the feature's architecture is dragged down by a 1100-line god screen (`nutrition.tsx`) and a 603-line god hook (`use-meal-logger.ts`) that **duplicates a core hook built for exactly this purpose** (`useMealLoggerActions`), a design-token system that has forked into 4-5 divergent local color maps causing a real visible inconsistency, and several near-byte-for-byte duplications (TheMealDB recipe matching web/mobile, the two Android widgets, the two share-card files). The problems concentrate at the top of the feature (screen/hook/orchestration/tokens), not in the leaf components underneath.

## Top 3 refactors
1. **Route mobile meal logging through `packages/core/hooks/useMealLoggerActions.ts`.** It already exists, is documented as "Used by both NutritionPage (dialog) and MealLoggerPage (full page on mobile)," and web already uses it — but `apps/mobile/src/app/(tabs)/nutrition.tsx:206-276` reimplements the same analyze/save/async-quality-scoring logic inline instead of calling it. Wiring mobile's URI→Blob adapter through this hook removes the single biggest DRY violation in the scope and the 603-line `use-meal-logger.ts` god hook shrinks accordingly.
2. **Break up `nutrition.tsx` (1100 lines) and `use-meal-logger.ts` (603 lines).** Extract the inline ~134-line "change goal" card (with its IIFE-computed preview), the frequent-meals grouping/sorting logic, and the direct `pb.collection('users')` profile-load/primary_goal-sync calls out of the screen into a dedicated component + core hook; split the meal-logger hook into capture/analysis/save concerns. Screens should compose sub-views and call core hooks, not own business logic and raw PocketBase calls.
3. **Centralize the fragmented design tokens.** `SCORE_COLORS` (quality-grade A-E colors) is independently redefined in at least 5 places — `packages/core/lib/style-tokens.ts` (canonical: `A: 'bg-green-500'`), `NutritionDashboard.tsx` (`A: 'bg-emerald-500'`), `QualityBreakdownPanel.tsx` (matches canonical, `green-500`), `MacroRing.tsx` (`A: 'text-emerald-400'`), and `NutritionShareCard.tsx` (custom `LIME` constant) — so the **same grade A shows a different color depending which component renders it on the same screen**. `MEAL_TYPE_COLORS` is separately redefined in 4 places with only one file importing it correctly. Fix: delete all local copies, import from `style-tokens.ts` everywhere (web's `NutritionDashboard.tsx` already does this correctly — mirror it).

## Done well

- **Consistent RN platform hygiene across the entire scope**: zero `TouchableOpacity`/`TouchableHighlight`, `expo-image` used everywhere (with `cachePolicy`/`recyclingKey` where relevant) instead of RN's core `Image`, matching `ui-pressable`/`ui-expo-image`.
- **`lib/image-upload.ts`, `nutrition-widget-snapshot.ts`, `sync-nutrition-widget.ts`** — excellent small modules: pure/testable functions, comments that explain *why* (the Expo `fetch`/`FormData` WinterCG quirk forcing `XMLHttpRequest`; the day-rollover snapshot logic), a dedup guard (`lastJson`) avoiding redundant widget writes, and platform-gated (`Platform.OS !== 'android'`) best-effort behavior that never throws.
- **`ai-elements/*` architecture** — clean compound-component composition (`Message`/`MessageContent`/`MessageResponse` via context, `Conversation`/`ConversationScrollButton` slot pattern), GPU-only Reanimated animations with proper `cancelAnimation` cleanup, and a properly-memoized `Response` — though note `reasoning.tsx` specifically is currently dead code (see Low findings).
- **Deliberate `memo` discipline where it's applied**: `NutritionDashboard.tsx`'s `MealCard` (stable `useCallback`s keyed by primitive id), `PantryTable`'s `Row`, `saved-recipes.tsx`'s `RecipeRow` — the intent is consistently right even where a caller-side closure occasionally undermines it (see Medium findings).
- **Documented platform tradeoffs instead of silent hacks**: MIUI/gorhom modal guidance followed throughout (`NutritionShareButton`, `BadgeCelebrationDialog`), `PantryConfirmSheet.tsx:142-143` explaining an index-key choice, `use-meal-logger.ts`/`meal-logger-views.tsx` comments capturing real Android crash workarounds, and a `cancelledRef` correctly guarding against race conditions when a user cancels in-flight AI analysis (`use-meal-logger.ts:269-270, 281-282, 310-311`).
- **Clean core-hook usage for data access** in the pantry slice: no hand-rolled PocketBase queries; all reads/writes go through `usePantryItems`/`useShoppingList*`/`useSavedRecipes`/`useWeeklyMealPlan`, with shaping logic (`computeRecipeCost`, `groupPantryByCategory`, `nextPurchaseInfo`) correctly living in `packages/core/lib`.
- **Clean SRP split for the meal-logger modal**: types/helpers (`meal-logger-shared.ts`), pure views (`meal-logger-views.tsx`), step components (`meal-logger-steps.tsx`), single state-machine hook (`use-meal-logger.ts`) — the internal structure of the logger is good even though the hook itself has grown too large (see High findings).
- **`QualityBreakdownPanel.tsx`** reuses one component for both the in-flight AI review step and the saved-meal dashboard view via a `compact` prop rather than duplicating markup — good compound/variant design.
