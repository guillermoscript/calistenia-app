# apps/web nutrition & pantry (NutritionPage, MealLoggerPage, PantryPage, ShoppingListPage, SavedRecipesPage, components/nutrition, components/pantry, components/ai-elements, WaterTracker, lib/receipt-api, lib/exif, lib/canvas-helpers)

## Grade

**B-.** The architectural direction is right — most read/write logic correctly lives in `packages/core` hooks (`useNutrition`, `usePantry`, `useShoppingList`, `useSavedRecipes`, etc.) and several pages (`PantryPage`, `ShoppingListView`, `PlanTab`) are exemplary thin orchestrators. But the newest, most complex surfaces (meal logger, share cards, recipe detail) have drifted: pure, platform-agnostic business logic keeps getting duplicated verbatim between `apps/web` and `apps/mobile` instead of landing in `packages/core`, one component (`MealLoggerContent.tsx`, 1441 lines) has become a god component, and a full canvas rendering engine is embedded inside a React component (`DailySummaryCard.tsx`, 818 lines).

## Top 3 refactors

1. **Move duplicated cross-platform pure logic into `packages/core`.** Three near-verbatim duplicates were found between `apps/web` and `apps/mobile`: `usePantryDepletion` (~95% identical, 78 vs 80 lines), the `pb.collection('users').getOne` profile-seed + shaping logic in `NutritionPage.tsx` vs `nutrition.tsx`, and the TheMealDB fetch/match/cache logic in `RecipeDetailDialog.tsx` vs `recipe-detail.tsx` (~60 lines). None of this code touches the DOM or RN-specific APIs — it belongs in `packages/core/hooks` / `packages/core/lib` with platform-specific side effects (haptics, Sentry import path) injected via callback.
2. **Split `MealLoggerContent.tsx` (1441 lines) by step, and de-duplicate its internal logic.** Extract `CaptureStep`/`AnalyzingStep`/`ReviewStep` subcomponents; move `compressImage` into `lib/canvas-helpers.ts` (or a new `lib/image.ts`); unify `handleAnalyze`/`handleAnalyzeText` (near-identical ~40-line bodies); and extract the eaten-time/duration pad+clamp construction (duplicated verbatim in `EditMealSheet.tsx`) into `core/lib/meal-time.ts`.
3. **Move `DailySummaryCard.tsx`'s canvas-drawing engine out of the component.** `drawSummaryCard`, `drawRichCard`, `rrect`, `drawGauge`, `ellipsis`, `makeCanvas` (~450 lines, zero React dependency) belong in a lib module. Unify the live-preview `useEffect` and `handleShare`, which currently duplicate the entire variant-branching/canvas-setup/image-loading logic to produce a preview vs. a shareable blob.

- **`apps/web/src/components/nutrition/MealLoggerContent.tsx:233-274` vs `323-358`** — `handleAnalyze` and `handleAnalyzeText` are near-identical ~40-line blocks (same abort/cancel setup, same food-normalization loop, same error handling), differing only in the `onAnalyze` args. - **`apps/web/src/components/nutrition/DailySummaryCard.tsx:167-604`** — A full canvas rendering engine (`drawSummaryCard`, `drawRichCard`, `rrect`, `drawRoundedImage`, `drawGauge`, `ellipsis`, `makeCanvas`, `ensureFontsLoaded`) lives inside a React component file with zero React dependency. Fix: export one `NUTRITION_GOAL_OPTIONS` constant from `packages/core` and import it in both places.

## Done well

- **`apps/web/src/pages/PantryPage.tsx`** and **`apps/web/src/components/pantry/ShoppingListView.tsx`** are excellent thin orchestrators: all business logic (queries, mutations, matching) lives in `packages/core` hooks (`usePantry*`, `useShoppingList*`), components only wire callbacks to UI. Model for how the other pages should look.
- **`apps/web/src/components/nutrition/plan/PlanTab.tsx:30-37`** — carries a genuinely useful code comment explicitly documenting *why* this 316-line tab was pulled out of `NutritionPage` (avoiding a repeat of "five components each generating plans their own way"). Rare, valuable self-documentation of an SRP decision.
- **`apps/web/src/components/pantry/use-pantry-depletion.ts`** — despite being duplicated with mobile (see High findings), the hook itself is well-scoped, documents its business rules inline, and reports failures to Sentry instead of swallowing them silently.
- **`apps/web/src/lib/exif.ts`** — dependency-free, pure, thoroughly documented binary EXIF parser; a good model for how framework-agnostic logic should be written and isolated.
- **`apps/web/src/lib/receipt-api.ts`** — minimal, explicit API client; deliberately surfaces real server error messages instead of swallowing them (documented in a comment).
- **`apps/web/src/components/nutrition/FoodNameInput.tsx`** — despite its size, implements a fully accessible combobox (proper `role="combobox"`/`listbox`/`aria-activedescendant` wiring) for a non-trivial multi-source (recents/catalog/OFF/AI) search UI.
