# Web scope: Dashboard / Profile / Progress / Reminders / Sleep / Onboarding / Calendar / Admin / Auth / Contexts

## Grade
**C+**. Several pages are exemplary (SleepPage, CalendarPage, AuthContext, BackgroundJobsContext, ProgressPage's composition) but the scope is undermined by three multi-hundred-line business-logic blocks that are copy-pasted verbatim between web and mobile (reminders UI logic, onboarding-save logic) or between two web pages (progress session-log derivation), plus two genuine god-pages (DashboardPage 721 lines, ProfilePage 840 lines) that do PocketBase I/O directly in the component instead of via a `packages/core` hook.

## Top 3 refactors
1. **Extract reminder business logic to `packages/core`.** `apps/web/src/pages/RemindersPage.tsx` (907 lines) and `apps/mobile/src/app/reminders.tsx` (1165 lines) independently reimplement: hour/minute clamping, day-of-week labels, meal icons, the pause-reminder time-slot generation loop, and `meal-`/`workout-`-prefixed id parsing/timeline building. `apps/web/src/lib/reminder-scheduler.ts` *also* reimplements the timeline-building logic a third time in the same app. Move all of this into `packages/core` (e.g. a `useReminderTimeline` hook + `buildPauseSlots`/`parseReminderId` utils) consumed by both apps and by the scheduler.
2. **Extract onboarding-save logic.** `apps/web/src/components/onboarding/OnboardingFlow.tsx` and `apps/mobile/src/components/onboarding/OnboardingFlow.tsx` contain identical `pb.collection('users').update(...)` / `pb.collection('body_measurements').create(...)` sequences at matching positions. `packages/core/lib/onboarding-state.ts` only holds the trivial "is onboarding done" localStorage flag — the actual save logic never made it into core. Add a `saveOnboardingData(userId, data)` core function.
3. **Turn `ProfilePage.tsx` into a thin view.** It's 840 lines with ~24 `useState` hooks and direct `pb.collection('users'|'nutrition_goals'|'user_health')` calls inline in the component. Mirror `SleepPage.tsx` (60-line body backed entirely by `useSleep`): extract a `useProfileForm`/`useProfileData` core hook that owns fetch/save/avatar-upload, leaving the page purely presentational.

## Findings

### High severity

1. **DRY — reminders UI/business logic triplicated.** `apps/web/src/pages/RemindersPage.tsx:71-81` (`clampHour`/`clampMinute`), `:14-23`+`:107-110` (`DAY_LABELS_STATIC`/`DAY_LABELS_KEYS`), `:49-54` (`MEAL_ICONS`), `:301-306` (pause-slot generation `for (let hr = startH; hr < endH; hr++) { for (let mn = 0; mn < 60; mn += interval) ... }`), and `:257,322,339` (`item.id.replace(/^(meal|workout)-/, '')`) are all re-implemented near-identically in `apps/mobile/src/app/reminders.tsx` (confirmed matching constructs at lines 64-84, 111-117, 379-389, 546-548, 587-631). None of this lives in `packages/core` even though `useWorkoutReminders`/`useMealReminders` (the data layer) already do. Fix direction: promote to a shared core hook/util.

2. **DRY — timeline-building duplicated within the same app.** `RemindersPage.tsx:160-194` (`timeline` `useMemo`) and `apps/web/src/lib/reminder-scheduler.ts:231-264` (`buildSchedulableReminders`) both build `meal-${id}`/`workout-${id}` prefixed items with the same `isPause` branching, written twice in the same codebase. Fix direction: reuse one mapper for both the on-screen timeline and the (now largely legacy) scheduler payload.

3. **DRY — onboarding PocketBase writes duplicated web/mobile.** `apps/web/src/components/onboarding/OnboardingFlow.tsx:132,150,165,209` and `apps/mobile/src/components/onboarding/OnboardingFlow.tsx:145,163,178,222` contain matching `pb.collection('users').update(...)` and `pb.collection('body_measurements').create(...)` calls — the actual save logic, not just UI. `packages/core/lib/onboarding-state.ts` is only 13 lines (LS-flag helpers), so the substantial part of "save onboarding" was never centralized. Category: DRY/Separation-of-concerns.

4. **DRY + perf — progress session-log derivation duplicated across two pages.** `apps/web/src/pages/ProgressPage.tsx:95-121` (`allLogs`) and `apps/web/src/pages/FreeProgressPage.tsx:28-52` (`freeLogs`) both parse `done_${date}_${workoutKey}` keys out of the `progress` dict and then, for each entry, re-scan the *entire* `progress`/`Object.values` collection to find matching exercise logs by date+workoutKey — an O(n²) pattern copy-pasted with minor variation. `packages/core/lib/progressUtils.ts` already exists (23 lines: `isFreeSession`, `filterProgressByType`) as the right home for this but wasn't used for the derivation itself. Category: DRY / `js-index-maps` (cache-friendly index instead of repeated linear scan).

5. **Separation-of-concerns — `ProfilePage.tsx` does PocketBase I/O inline.** Direct `pb.collection('users').getOne/update`, `pb.collection('nutrition_goals').getFirstListItem/update`, and avatar `FormData` upload all happen inside the 840-line page component (`apps/web/src/pages/ProfilePage.tsx:103,121,164,169,187,205,212`), with 24 local `useState` fields for form state. Contrast with `SleepPage.tsx`, which delegates entirely to `useSleep`. Category: SOLID-SRP / Separation-of-concerns.

### Medium severity

6. **Correctness-smell — unescaped PocketBase filter string.** `apps/web/src/pages/AdminPage.tsx:69`: `` filter: `email ~ "${q}" || display_name ~ "${q}"` `` interpolates raw user input into a PB filter string instead of using `pb.filter('email ~ {:q} || display_name ~ {:q}', { q })` — the pattern the rest of the codebase uses correctly (e.g. `ProfilePage.tsx:122`). A `"` in the search box breaks the query silently. Fix: switch to `pb.filter`.

7. **SOLID-SRP — `DashboardPage.tsx` god page.** 721 lines; owns water/sleep/leaderboard/feed/streak-milestone/nudge/goals/quick-actions/config-panel, including a large IIFE (`apps/web/src/pages/DashboardPage.tsx:310-389`) computing "today's workout hero" state directly inside JSX. Fix: extract `TodayWorkoutHero` component and a `useDashboardData` aggregator hook.

8. **KISS — giant `useState` cluster instead of reducer.** `ProfilePage.tsx:31-60` declares ~24 independent `useState` calls for one form. Fix: consolidate into a single reducer or the extracted hook from refactor #3.

9. **KISS — 9 parallel by-date `useState` slices.** `CalendarPage.tsx:61-69` (`cardioSessions`, `circuitSessions`, `nutritionByDate`, `waterByDate`, `sleepByDate`, `weightByDate`, `measurementByDate`, `photosByDate`, `lumbarByDate`) are all populated together from one `fetchMonthActivity` call (`:87-98`) yet live as 9 separate state variables. Fix: one `monthData` state object set in a single `setState` call.

10. **Correctness-smell / i18n gap — hardcoded Spanish strings.** `apps/web/src/components/InstallPrompt.tsx` hardcodes all user-facing copy in Spanish (lines 93, 96, 103, 112-127, 134, 143, 149) instead of using `useTranslation()`/`t()`, unlike every other component in scope (which consistently uses `react-i18next`). English-language users see untranslated Spanish. Given the repo's own i18n usage guardrail (`usage.test.ts`, #444/#445), this component appears to have slipped through because it has no `t(...)` calls to scan.

### Low severity

11. **KISS/dead code — legacy scheduler retains unused code paths.** `apps/web/src/lib/reminder-scheduler.ts` header explicitly says it's "LEGADO, solo se usa para LIMPIAR" (legacy, only used to clean up) — only `cancelAllScheduled` is called from `RemindersPage.tsx:206`. `scheduleAll`, `fireNotification`, `startPeriodicCheck`/`stopPeriodicCheck`, `setupVisibilityRescheduler`, and `buildSchedulableReminders` (lines 96-276) are dead in production flow. Fix: if truly unused, delete and keep only the cleanup path + a comment explaining why cleanup is still needed.

12. **KISS — icons defined as local functions per-page instead of shared.** `RemindersPage.tsx:872-907` defines `XIcon`/`CheckIcon`/`PencilIcon`/`BellIcon` as bottom-of-file local components; likely re-defined again in sibling pages (out of audit scope to confirm broadly, but worth a repo-wide sweep).

13. **React-perf (minor) — unmemoized static data rebuilt every render.** `LumbarPage.tsx: getProtocols(t)` (called at `:261`) rebuilds the full protocols/exercises array (with `t()` calls) on every render of `LumbarPage`; not expensive but a candidate for `useMemo(() => getProtocols(t), [t])`.

14. **KISS — redundant field on `GoalDef`.** `DashboardPage.tsx:80-96`: every `GoalDef` carries both `label` (Spanish fallback string) and `labelKey` (always present for all 5 goals, always taken via `goal.labelKey ? t(goal.labelKey) : goal.label` at `:121`) — the `label` field is dead weight since `labelKey` is always defined.

## Done well
- **`SleepPage.tsx`** is a model page: all data/mutation logic lives in `useSleep` (core), the component is presentational, ~60 lines of real logic in a 412-line file (rest is JSX).
- **`AuthContext.tsx`** and **`BackgroundJobsContext.tsx`**: clean provider pattern — state/actions split into memoized objects, and `BackgroundJobsContext` correctly centralizes a *single* shared polling interval + SW listener instead of letting each consumer run its own (avoids duplicate timers, a common React anti-pattern this codebase avoided).
- **`CalendarPage.tsx`** correctly reuses `packages/core/lib/monthActivity.ts` (`fetchMonthActivity`) — the same TZ-correct bucketing used by the native calendar — rather than ad-hoc fetching per source.
- **`AppTour.tsx`** dispatches via a `PAGE_TOURS` lookup table (`replayTourForPage`, `:673-686`) instead of an if/else chain per page — good OCP even though the file is long.
- **`packages/core/hooks/useWorkoutReminders.ts`/`useMealReminders.ts`**: solid optimistic-update pattern (`onMutate`/`onError`/`onSuccess` with localStorage write-through and stable public API), well-commented on tricky race conditions (e.g. explicit `newEnabled` param to avoid reading already-flipped cache).
- **`ProgressPage.tsx`** composition: delegates to ~13 focused child components (`ProgressSummary`, `ExerciseChart`, `WeightTracker`, `BodyPhotosTimeline`, etc.) rather than inlining everything — good compound-component style even though the derivation logic feeding them has the DRY/perf issue noted above.
