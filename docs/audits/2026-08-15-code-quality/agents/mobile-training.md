# apps/mobile — session / training / programs / library / calendar

Scope audited: `apps/mobile/src` session & training surface (screens, components, contexts, lib) as assigned.

## Grade

**C+**

The *primitives* are genuinely good — `session-machine.ts`, `live-activity-state.ts`, `reorder.ts`, `RestPanel`, `CountdownRing`, `useFreeSessionChat` are pure, composable, tested-shaped code, and a previous refactor already killed three copies of the countdown. What drags the grade down is the layer above: `SessionView.tsx` is a 1128-line god component holding 6 states + 8 refs + 3 shared values, the active-session truth is spread across SessionView locals / context state / context refs / storage / remote sync with a `resumeEpoch` remount hack papering over the seam, and the *same* session logic exists in three places across web and mobile — already diverged in a way that changes behaviour.

## Top 3 refactors

1. **Move the session state machine + workout-key naming into `packages/core`.** `buildSteps` exists three times (mobile `lib/session-machine.ts:13`, web `SessionView.tsx:55`, web `ActiveSessionContext.tsx:282`) and the mobile copy has already diverged on `sets=0`. The `workoutKey → title` resolver exists three times *inside mobile alone*, with two different i18n keys. One core module, both apps import it.
2. **Break up `SessionView.tsx` (1128 lines) and give the active session one owner.** Extract `ExerciseScreen`, `NoteScreen`, `CelebrateScreen`/`TimingBar` into `components/session/*`, and collapse `stepIdx/phase/setsCount/transitionType/pendingStepIdx` into a reducer driven by `session-machine.ts` — the machine already returns the decision, the component just re-implements the dispatch by hand.
3. **Lift the PocketBase data layer out of the screens.** `app/program/[id].tsx` and `app/session-detail.tsx` between them run 4 ad-hoc `pb.collection(...)` calls, `any`-typed row mappers and 4 silent `catch {}` blocks inside render components. These belong next to `useSessionDetail` / `usePrograms` in core.

## Done well

- **`components/training/*` is a genuinely good extraction.** `RestPanel` takes primitives + `children` and no domain type (*"Recibe segundos y callbacks, nunca un `Step` ni un `BattleSnapshot`"*), `CountdownRing` animates with a single `withTiming` on a shared value so React paints zero frames during a countdown, and `components/circuit/CountdownRing.tsx:1-11` documents killing the third copy of the pattern. This is textbook `patterns-children-over-render-props` + `animation-gpu-properties`.
- **Pure, framework-free logic is genuinely pure.** `session-machine.ts`, `live-activity-state.ts`, `reorder.ts`, `detect-day-type.ts`, `catalog-to-exercise.ts` have no React, no side effects and obvious test seams — the problem is only that they live in `apps/mobile` instead of `packages/core`.
- **`lib/use-free-session-chat.ts:69-71`** derives `sessionExercises` instead of resetting edits from an effect, and the comment explains exactly which bug that killed. Model example of `rerender-derived-state-no-effect`.
- **`app/(tabs)/library.tsx:200` and `(tabs)/programs.tsx:240`** do list rows right: `memo`'d row, id-based `keyExtractor`, hoisted `openX` callback with the id passed down (`list-performance-callbacks` cited in a code comment at `programs.tsx:93`).
- **No `TouchableOpacity`, no `react-native` `Image`, no falsy-`&&` crash sites** anywhere in the scope — `Pressable` + `expo-image` + `!!x &&` / ternaries throughout, and `SafeAreaView` edges are set deliberately per screen.
- **The hairy Reanimated bugs are documented rather than re-broken.** `SessionView.tsx:829-834` explains why the swipe snap moved out of the `withTiming` callback (*"mutar un shared value + runOnJS anidados … crashea en Reanimated 4 (release)"*).
